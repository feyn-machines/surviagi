# 本体版本与身份

本体只有一个，版本号写在 `schema/schema.json` 里，与运行批次、指标方法、进度值分开。当前为 `2.4.0`，继承 `2.3.0` 的全部数据，后者依次继承 `2.2.0`、`2.1.0`、`2.0.0`，再往前是 `1.0.0`；`1.0.0` 来源为混合平台包 `0.0.1`。每一版的来源版本和根哈希都记录在清单里，旧版保留。

受控词表各自带版本。事件类型词表的版本写在每条更新的 `kind_vocabulary` 标记里并进入判定哈希，只有它的词条或边界变了才升；本体升版本不动它，否则新旧抽取会被误判为不可比。

## 向前生效

定义从某一版开始生效，不回头改写已有的数据（`rule:definitions-take-effect-forward`）。

- 类、属性、关系、词表项可以写 `since`（从哪一版开始有）和 `until`（到哪一版为止还在写）。没有 `since` 的视为一直存在。词表自带版本时，词表项的 `since` 指词表版本，其余指本体版本。
- 每条更新在 `schema_version` 里记录它被提取时的本体版本，在 `kind_vocabulary` 里记录当时的事件类型词表版本。它按那一版解读。`schema_version` 为空表示早于 2.2.0。
- 新增不补旧：新属性在更早的更新上为空，含义是“当时没有记录”，不是“没有”。
- 失效不删除：失效的定义留在 schema 里并标 `until`；旧数据上的值原样保留；新的提取不再写。
- 默认不重抽。主动重抽某一批时，身份相同的更新在原行上升级到新版本；升级前的内容保留在当时的提取归档里，归档不可覆盖。
- 已执行的数据库迁移是冻结的。为它生成的约束文本按当时的词表版本渲染，所以词表增加词条不会改写旧迁移；新词条进入新的迁移，并挂在新的 `kind_vocabulary` 标记之下。
- 读取事件时按“属于同一系的词表版本”筛选（`event_kind` 的 `lineage`），不按单个版本号做等值比较。

| 升级 | 本体变更 |
| --- | --- |
| patch，例如 `1.0.0 → 1.0.1` | 名称/翻译修字和不改变含义的说明修正 |
| minor，例如 `1.0.0 → 1.1.0` | 兼容增加概念、关系、外部映射或可选字段 |
| major，例如 `1.0.0 → 2.0.0` | 删除/替换身份、改变类型或既有定义范围、改变关系含义，或不兼容字段变化 |

一次变更按最高级别升级。事件新增或评论计数变化不改变本体版本。结构版本不表示数据成熟度或生产发布。

## ID 固定

- 整个 ID 是身份。名称、中文译名和显示顺序改变时沿用 ID；不能根据新名称或新路径重新生成它。
- 本包逐项继承平台 v0.0.1 的概念、关系和映射 ID。关系 ID 中原有文字不会随新增关系类型字段而重算。
- `kind` 字段决定类型，不能从 ID 中的英文片段猜类型。例如历史 ID 里包含 `market` 的条目也可能是 `work`。
- 真正新增概念才分配新 ID。拆分、合并或替换必须明确记录旧新身份的对应与停用理由，不能复用已停用 ID。
- 旧版本保持完整；历史引用应同时带本体包版本和概念 ID。

## 封存与构建

2.0.0 起每个包包含 `schema.json`（类型定义）、由它生成的 `data-format.json` 与 `ontology.ttl`、全量 JSONL、闸门与公司名单、可读目录和 manifest；1.0.0 包含 `model.json` 和旧的 `schema.json`（当时的数据文件格式）。manifest 记录所有文件的字节数、行数和 SHA-256；`manifest.sha256` 保存 manifest 本身的哈希。

构建先写独占临时目录，完整验证后再移到最终路径；已存在路径拒绝覆盖。校验同时验证模型/Schema 合同及实际跨记录约束，拒绝多余文件、篡改、非法引用和运行数据集合。

`pnpm ontology:seal` 封存 schema 里写的版本：上一版的每个数据文件逐字节继承，验证时核对哈希相同，这就是身份迁移检查。导出文件和数据格式文件在验证时由封存的 schema 重新生成并比对。不能通过手改 manifest 版本号假装完成升级。

SHA-256 用于发现被改写的内容，不认证发布者身份。没有执行数据库导入、Git 发布或网站激活。
