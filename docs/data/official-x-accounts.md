# AI 公司官方 X 多账号名单

核验日期：**2026-09-11**。当前覆盖 **13 家公司、51 个启用账号**；另保留 **8 个未启用账号**。百度 / 文心按项目决定排除。这是已核验的账号集合，后续发现有官方依据的相关账号继续追加，不按公司设置一个账号的上限。

**官方 X 原始发布是进度记录的主要来源。一家公司可同时对应公司、模型、产品、开发者、研究、云平台及新闻账号。** 同一产品也可以有多个来源账号；每个账号单独记录身份、用途和采集覆盖。

## 如何确认官方身份

取得匹配的 X 数字用户 ID 后，至少保留一种可复查的身份依据：

- 官网、官方文档、官方仓库的明确链接或网站身份声明。
- 已确认官方 X 对自有产品账号的明确介绍，保存原帖、发布账号及其 ID；普通提及或回复只作为线索。
- X 返回的组织关联标识指向已经确认的公司账号，并核对母账号 ID。它与普通蓝标不同；[X 官方说明](https://help.x.com/en/using-x/premium-business)解释了组织管理关联账号的机制。

员工个人账号不因有组织关联就进入本公司／产品名单。名称相似、普通蓝标、账号自述以及链接到公司网站，均不足以单独确立官方归属。

## 数据与采集规则

- [账号 JSON](../../datasets/official-x-accounts.json)：59 条记录，含启用状态、公司、用途、当前 ID、显示名和身份依据，可直接供采集器读取。
- [X 身份查询记录](../../datasets/evidence/x-account-profile-checks-2026-09-11.json)：包含候选与失败尝试；出现于观察记录不等于被确认官方。
- [官方 X 账号关系证据](../../datasets/evidence/x-account-relationships-2026-09-11.json)：保存官方产品介绍和组织关联。
- [国内基础查证](../research/chinese-official-x-accounts.md)与[增量查证](../research/chinese-official-x-multi-account-expansion.md)。

**不得按公司名去重账号。** 每个启用 handle 都生成独立查询，按账号报告成功、失败、未查询及时间范围。同一发布可以被多个官方账号同时介绍：后续合并的是更新事件，仍保留各账号原帖与全部来源链接。

账号 JSON 是数组格式。`pnpm data:official:import` 把它导入数据库 `source_accounts`（2026-09-28 起爬虫从表里读账号），名单更新后重跑导入。采集由爬虫组件为每个启用账号生成一条时间线任务，命令见 [X 采集爬虫运行手册](../development/x-crawler.md)（2026-09-27 起，原技能脚本入口已移除）。

全名单查询使用 `--account-limit 0`。`--limit` 是整次运行的总条数预算，不是每个账号的预算；达到上限或失败后，未查询的账号必须算作覆盖缺口。本轮为核实账号关系进行了有限 X 搜索，没有启动定时监控或近 30 天全量采集。

爬虫按名单里的数字 ID 认账号：帖子的 `author_id` 与名单不同，就隔离为 `author_identity_mismatch`。数字 ID 相同而用户名变了，是账号改名（2026-10-16 起）：帖子照收，记在名单里的 `handle` 名下，运行文件的 `handle_changes` 写明新用户名；名单用 `x_handle_now` 记下现在的用户名，`handle` 本身不改，因为它生成数据库里的账号键。此前改名的帖子全被隔离：@Microsoft365（现 @MSFTCopilot）自 2026-09-21、@SpaceXAI（现 @SpaceXSI）自 2026-10-10 起没有一条入库，已用 `pnpm data:recover:renamed` 从保留的运行文件里补回窗口内的 30 条，没有再访问 X。账号身份不等于所有内容都是产品公告；综合账号宣传、转发和自动回复需单独识别。

只从实际取得的原文建立事件，分别记录官方宣称、演示、测试开放和正式可用。账号覆盖数量不用于计算 AI 接管百分比。
