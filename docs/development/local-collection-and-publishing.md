# 本地采集与网站发布

当前的网站构建、发布与回滚流程见[网站部署手册](deployment.md)。

阶段说明：本文保留较早的网站上传/发布方向。当前一期只实现本地处理、入库、指标和实验进度验证，实际状态及命令以[本地数据链路](local-data-pipeline.md)为准；本文的上传、激活和网站集成不作为一期要求。

确认日期：2026-09-12。首阶段采用本地采集、上传标准化数据、Next.js 全栈展示。先在本地运行积累实际数据；采集程序无需部署到网站服务器，也无需单独建立 FastAPI 后端。

## 运行方式

1. 本地固定 Python 采集程序读取已启用的来源配置，获取新材料与互动快照，保存原始材料、覆盖记录、失败原因和恢复状态。
2. 本地处理来源身份、标准化、去重、事件关联与行业映射；AI 推演使用明确版本的材料和方法，产出事件及进度快照。
3. 从本地材料中生成可发布的数据批次，校验字段、来源、隐私和引用完整性，再上传到网站使用的数据存储。
4. Next.js 提供页面与必要查询接口，读取已激活批次，并显示最近更新时间及采集覆盖。网页访问不触发爬虫。

当前只有独立采集脚本、一次试采和历史试算；自动推演、上传器、线上数据存储、持续调度和部署尚未实现。存储供应商及上传认证方案尚未选择，不把架构方向写成已运行能力。

## 文件职责

| 路径 | 职责与发布范围 |
| --- | --- |
| `src/`、项目配置、锁文件 | Next.js 应用源码，可进入 Git 与正常应用构建 |
| `datasets/` | 版本化合同、来源目录、脱敏观察与历史样例，可经检查提交；不自动等于网站当前数据 |
| `docs/`、`CONTEXT.md`、`DESIGN.md` | 可公开的项目说明与领域／设计规范 |
| `design/system-v1/` | 本项目可复用设计实现及带许可证的字体；网站按实际引用打包 |
| `design/reference/` | 第三方参考原件保留本地；只提交来源清单等允许的元数据 |
| 根目录 `data/` | 本地原始档案、数据库、运行状态及待上传批次，整体不进入 Git |
| `.agents/`、`.claude/`、`.codex/` 等 | 本地工具、技能、会话与设置，不进入 Git 或网站源码包 |
| `AGENTS.md`、`CLAUDE.md` | 本地 Codex／Claude Code 指引，延续本项目的排除策略 |

“标准化数据上传”是对某个已验证批次的发布操作。它不授权上传整份工作目录、完整社交归档、数据库备份或第三方参考素材。具体禁止项见 [SECURITY.md](../../SECURITY.md)。

## 上传契约

未来上传器应满足以下要求：

- 每批至少包含批次 ID、数据格式版本、生成时间、来源覆盖、引用的行业／方法版本，以及文件列表与校验值。
- 内容仅包括明确选择的可发布字段：标准化事件、来源链接、可公开实体信息、指标快照、带假设与版本的进度估计。缺失值、待核状态和采集缺口保留。
- 完整上传到新批次，验证成功后再切换当前版本。失败保留上一版，重复上传同一批次不产生重复事件或重复进度。
- 本地爬虫的账号登录状态、代理凭据和原始运行日志只服务本地采集。上传凭据独立配置，不进入代码或浏览器资源。
- 原始抓取、企业采用判断和 AI 推演版本分别可追溯。首次新口径推演不是当天能力增量；旧 24.28 分仍是历史试算。

采集来源使用当前[元数据复核清单](../data/metadata-reconfirmation-2026-09-12.md)。九行业来源保持原始分组；人物候选不会因进入目录自动变成启用账号。

## 开发入口和检查

在项目根目录使用 Codex 或 Claude Code。Codex 从 `AGENTS.md` 进入共享 `CLAUDE.md`，Claude Code 直接读取后者；两个本地文件维护一份共同指引。它们没有提交到 Git，新机器需要从可信本地配置恢复，不能以为普通 clone 会带上。

入口机制参考 [Codex 项目指引](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与 [Claude Code 项目指引](https://code.claude.com/docs/en/memory)。本次核对了项目本地入口和 Next.js 自动生成器的兼容性，未启动额外收费的 Agent 会话进行验收。

安装依赖使用 `pnpm install --frozen-lockfile`，启动网站使用 `pnpm dev`。代码或配置变更后运行 `pnpm check`；暂存准备提交的文件后运行 `pnpm security:staged`。设计资源改动先执行 `pnpm design:build`，然后检查生成结果。

`pnpm check` 扫描当前公开候选文件，包括未暂存的新文件；暂存后由 `pnpm security:staged` 对 Git 索引再次扫描（仓库不使用托管 CI，这一步在本机做）。检查不会扫描和打印被忽略的本地秘密，强制暂存的禁止路径会被拦截。规则扫描仍需配合人工审阅提交内容，尤其是原始材料或未验证的数据导出。
