# 名单健康与维护实施约定

2026-11-05 · Refs #23 · [来源覆盖规则](../data/source-coverage-policy.md)

本文规定 #23 后续实现的统计、复核和验收边界，**不是已上线功能说明**。目前没有一条命令完成本文全部要求。不要把本文的建议周期、报告字段或原因分类当作已经存在的本体属性、SQL 枚举或启用规则。

## 现有机制与缺口

`scripts/data_pipeline/panel.py` 的 `derive_state` 按本体 `rule:panel-lifecycle` 和检查事实推导状态，`refresh` 写入变化；不要另设人工直接启用入口。现有状态为 `candidate`、`identity_confirmed`、`enabled`、`suspended`、`retired`。`source_account_checks` 采用追加记录；检查类型以最新迁移和本体为准，不能沿用迁移 025 中后来已被移除的 `yield`。

已有数字账号 ID 核对、个人隶属关系时效、休眠和连续核对失败的规则。缺口是按窗口的完整产出报告、跨来源候选队列、身份本身的分层时效及可回查的状态转换原因。不能仅凭 `state_changed_at` 宣称已有完整转换历史。

## 窗口与产出统计

报告必须接受显式起止时间和统计时点，使用带时区的半开窗口 `[start, end)`，默认展示近 30 天，显示 Asia/Taipei 和 UTC 边界。按帖子发布时间归窗；处理时间、采集完成时间另列。对相同窗口重跑只更新处理覆盖，不重复累加。

| 指标 | 口径与限制 |
| --- | --- |
| 帖子数 | 以平台和帖子 ID 去重，归到稳定数字账号 ID；改 handle 不拆成两个账号。转发单列，不充当原创 |
| 更新数 | 窗内帖子关联的不同更新 ID；一帖多更新可大于帖子数，多帖关联同更新只算一次 |
| 观察数 | 窗内来源帖子关联的不同观察 ID；多账号共同来源分别归因，全局总量再去重 |
| 话题主张数 | 按持久化主张 ID 去重；同帖有多条主张允许大于帖子数，不用来冒充独立来源数 |
| 被丢弃帖子数 | 有明确终态丢弃记录的不同帖子 ID；各抽取阶段分别报告，不用“帖子减更新”推算 |
| 主要丢弃原因 | 从持久化终态原因聚合；没有原因的明确记为未知，不从帖子正文猜测 |
| 最近发帖时间 | 截至统计时点可见的最近原始帖子时间，允许早于窗口；没有采集覆盖时记未知 |

一帖可能同时形成更新、观察和主张，上述指标不能相加作为帖子分区。每个处理阶段另列成功、明确丢弃、待处理和失败；失败不是丢弃。明确说明按当前关系统计还是历史快照，不能把后补抽取伪称为当时已有。

采集成功且覆盖完整但没有帖子才是已观测零。未启用、未采集、限流、账号不可达、抽取失败、历史原因未记录均分别标记；缺数据不能触发低产出退役。账号间产出率比较必须给出有效分母、覆盖率和样本量。

## 统一候选队列

合并名单导入、搜索回流和审核通过的读者/Agent 推荐；以平台数字 ID 去重，未解析 ID 时按平台与规范化 handle 暂归并，后续解析需保留别名和全部来源记录。审核通过的推荐不是身份确认，不自动启用。保留发现时间、来源引用、缺失信息、最近处理及下次处理时间。

优先顺序：身份冲突或疑似易主的已启用账号；已确认覆盖缺口中的候选；被不同来源反复引用的候选；其余按最早发现时间。重复推荐或同一作者重复发帖不增加独立引用数。缺口依据来源覆盖规则，不能凭关注数或正面态度加权。未分类候选要标明缺角色、姓名还是身份证据，不靠模型猜测启用。

建议每次现有每日运行后或人工唤醒时生成积压摘要，每周在有会话执行时复核最老候选；没有唤醒不承诺按时执行。不得新增调度。一次处理未完成的候选保留原因和下一步，不删除、不伪装成拒绝。既有已确认范围内按规则处理；新增范围的取舍进入 STATUS 待决策。

## 身份时效与维护动作

身份核对和内容核实分别进行。核对数字 ID、第一方身份链接、所属组织、角色和利益关系；转岗只改变其生效日期后的关系，不改写旧帖身份。handle 改名且数字 ID 相同保留账号历史；数字 ID 冲突或疑似易主先暂停使用其身份背书，再核对。一次网络失败记未知，不等同封停或易主。

建议复核周期为：第一方发布和独立评测用途 90 天，具名采用者和市场/就业测量用途 180 天，观点用途 365 天。多用途取最短周期，未知身份立即待复核；明确身份变化立即提前复核。这些是待实现的运行默认值，正式生效前必须纳入唯一的本体规则及版本流程，不能在报告脚本另维护一套规则。现有隶属关系复核要求继续有效，不能被较长建议周期放宽。

| 情况 | 处理约束 |
| --- | --- |
| 长期低产出或只转发 | 覆盖完整后列为人工复核建议，不自动否定身份，也不以观点方向决定保留；先核实采集和抽取缺口 |
| 身份过期 | 标为待复核；实现时效门控后，不再作为已确认身份的高要求证据，历史观察保留当时身份与核对时点 |
| 身份冲突、明确封停或失败核对 | 追加检查事实，按本体规则推导暂停；达到本体现有连续失败条件才退役，不在文档复制阈值 |
| 休眠、排除或隶属关系失效 | 走既有生命周期条件；恢复需新检查通过并重新推导，不直接改 enabled |
| 纠错或恢复 | 追加带依据的纠正检查，保留原检查及所有转换；退役后的恢复也必须有明确新事实 |

每次转换需保存账号、前后状态、生效时间、触发检查引用、原因、执行来源及规则版本。重复执行不新增相同转换；同一事务内保存检查、状态和转换历史，失败全部回滚。人工决定应关联证据和理由，不把自由文本变成新的状态枚举。身份证据过期的门控需覆盖报告和下游证据使用，只有报告告警不足以验收。

## 健康报告与交付验收

后续交付一个只读命令生成健康报告，报告和状态刷新明确分开；不隐式采集、调用模型、刷新状态或发布数据。默认可分享摘要只含计数、窗口、覆盖限制和规则版本：各状态数、低产出建议数、不可达数、身份到期数、各候选来源及等待时长分布。类别可能重叠，给出账号去重总数。账号标识、来源 URL、推荐人、正文、内部理由及逐账号队列仅写本地受限文件，不上传 GitHub。

实现验收需合成数据与真实克隆库测试覆盖：

- 窗口左右边界、时区、重复采集、handle 改名、同帖多产出、多来源观察去重。
- 完整零产出、缺采集、失败、待处理、未知丢弃原因分别显示，不能混为低产出。
- 三类候选归并、缺分类、重复推荐不加权、确定性排序与积压年龄。
- 身份到期临界点、多用途最短周期、组织和个人、转岗生效日期、易主和未知网络结果。
- 五种状态的可达转换、连续失败退役、追加纠错恢复、幂等执行及事务回滚；历史原因可回查。
- 默认摘要不含账号及私有信息；报告只读；身份证据过期后下游不再享有已核对身份待遇。

涉及实体属性或规则变更必须先更新私有本体，再生成投影及迁移；开发用私有本体副本和 `OAW_DATA_DATABASE` 克隆库，避开共享本体/迁移串行队列。代码需 `pnpm check`，管线需 `pnpm data:setup` 与 `pnpm data:test`。不修改两个现有每日任务。当前阶段只交付此约定，#23 的命令、状态留痕和真实报告验收仍未完成。
