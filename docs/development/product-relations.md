# 产品、观察对象与采用关系

产品是应用或服务，模型是它可能使用的训练模型；两者不共用实体编号。
本体的 `Product`、`ProductAvailability`、`adopts`、`invests_in` 是定义来源，
本功能不改变历史观察的编号、`subject_key` 或抽取原文。

## 写入与解析

在本地准备受信任的目录文档，保存在忽略的 `data/` 下，执行：

```sh
pnpm data:products:import -- data/product-catalog.json
pnpm data:resolve:subjects
pnpm data:publish:snapshot
node scripts/check-public-contract.mjs
```

分支验证必须先设置 `OAW_DATA_DATABASE` 指向私有克隆库，不能把日常库当测试库。
目录文档是人工整理的来源断言，不是网页爬虫；录入者必须核对链接正文、日期与身份。
只有明确的字段进入库；未知字段、同编号的不同内容、无日期可用性来源的产品，整份拒绝。
相同内容重放不新增记录。更晚的阶段、可用性或投资记录使用新编号，不能覆盖旧记录。

文档可含四个数组，未提供的数组表示本次不导入该类：

| 数组 | 字段（未给出的可空字段写入 null） | 依据 |
| --- | --- | --- |
| `products` | product_id, org_id, owner_name, name, category | 产品及制作方；每个产品须已有或同时导入可用性来源 |
| `availability` | availability_id, product_id, as_of, stage, channel, region, audience, price, source_url | 该日的阶段、渠道与地区；不推断全球可用，不把宣布日期当上线日期 |
| `adoptions` | adoption_id, org_id, adopter_name, product_id, model_id, stage, adopted_on, scale, observation_id | 必须与有来源、未被拒绝且未并入他处的采用方观察的身份与对象一致；阶段须由来源明确支持 |
| `investments` | investment_id, investor_org_id, investee_org_id, stake, started_on, ended_on, source_url | 官方投资披露；金额不当持股比例，宣布时间不当交割或持股起点 |

实体编号和词表取值从公开契约查询，不在这里维护第二份取值清单。
可用性与投资 URL 必须是 HTTP(S) 链接；SQL 同时校验外键、日期与阶段。
投资双方必须在组织目录中；未登记的组织先走现有组织录入流程。

解析只比较完整名称、实体编号和已记录的模型别名，统一大小写、Unicode 与分隔符。
读取观察运行保留的原始对象名称；旧记录无此字段时才使用 `subject_key`。
多个名称指向不同实体、产品与模型重名、未知名称、组合对象均保持未解析，
不会按子串或相似度选择。自动模型解析限于已确认的具体发布版本：家族名可能指应用，
候选模型也可能是误收的产品。产品必须先入产品目录。解析不会建立产品到基础模型的推测关系。
未解析保留原文和两个空对象外键；命令报告未解析名称及数量。

解析之后，只有组织已登记、角色为采用方且证据明确是自身使用或生产使用的观察，
自动生成对应的采用阶段，带观察编号、来源提供的规模与发生日期。
没有发生日期就保持 null，不拿发帖日补齐。个人、身份未明的采用方、演示、厂商宣传和
评测不会自动成为组织采用；这些记录仍可参与观察查询。需要其他采用阶段时走有来源的显式录入。
日常处理在观察映射之后执行这个无需模型调用的步骤，失败时停止发布。

## 发布与证据边界

契约 1.11.0 新增 `products`、`product_availability`、`adoptions`、`investments` 集合。
采用只发布仍有来源且未被拒绝、未并入他处的观察对应关系，引用同一快照中的观察头。
投资保留来源与起止日期；空日期不能用来判定过去某天的独立性，未查到投资也不等于独立。
原文关系与机器判断的字段分级见各实体 JSON Schema；采用阶段仍是机器字段，不能冒充人工确认。
关系属性类型与阶段词表直接从本体关系投影，所有字段都出现，未知为 null。

服务器数据发布包含这四个集合及计数、哈希；网站读取器接受新集合，也兼容没有它们的旧发布。
没有集合的旧发布保持未知状态，不能补成“零条”。新代码须先上线，再激活含新集合的数据。
目录、真实观察、导入文件、报告与快照均不进 GitHub；源码、契约与测试通过 PR 交付。

## 验证

`pnpm data:test` 覆盖产品与模型分开解析、冲突/候选/家族不强配、身份与证据门控、
原观察身份不变、采用来源与日期、重复执行、目录整份回滚和公开字段投影。
`node --test scripts/tests/public-contract.test.mjs` 验证关系属性投影与空值/阶段约束。
真实克隆库运行后，记录命令返回的分母、归入比例、采用数量和主要未解析名称，
并对生成快照运行契约检查；这是该次数据覆盖情况，不是模型能力或全球采用率。
