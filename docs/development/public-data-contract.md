# Public data contract / 对外数据契约

Issue #27, part of the evidence-ledger redesign (#34). Contract version **1.6.0**, ontology schema **2.6.0**.

The ontology schema is the one type definition. The public contract is generated from it, so an agent can learn from one place which entities exist, what each field means, how far it can be trusted, and how the format evolves.

本体 schema 是唯一的类型定义。对外契约由它生成，Agent 可以在一个地方了解有哪些实体、每个字段的含义、可信到什么程度，以及格式如何演进。

## Files / 文件

Generated by `pnpm ontology:projections` into `public/contract/v1/` and served at `https://surviagi.com/contract/v1/`:

| File | Content |
| --- | --- |
| `index.json` | contract and ontology version, entity list, grades, wire rules, retired collections |
| `schemas/<Entity>.schema.json` | JSON Schema (draft 2020-12) of one entity |
| `openapi.json` | OpenAPI 3.1 description of `/api/agent/search` and `/api/agent/record` |

`pnpm ontology:check` re-derives all of them and fails on drift. Never edit them by hand.

Types, cardinalities and enumerated values come from `datasets/ontology/schema/schema.json`. The *publication view* — which classes and properties are public, each field's grade, the snapshot file that carries an entity, denormalised snapshot fields — lives in `scripts/lib/public-contract.mjs`. Every property named there must exist in the ontology, and every ontology property of a public class must be either public or listed in `omit`; the generator throws otherwise, so a property added to the ontology cannot silently become public or silently go missing.

## Entities / 实体

Concept (market, work, occupation, …), Organization, Person, SourceAccount, Event, Model, Provider, Product, ProductAvailability, Observation, ObservationSource, ObservationFact, Topic, TopicOption. Articles are not in the ontology (they live in the `editorial` schema) and join the contract with the article/observation work in #29/#32. Level readings (`chain`, `markets`, `tasks`, `progress`, `coverage`) are outside the contract and listed as retired in `index.json` (#35).

Snapshot files under the contract: `work`, `occupations` (1.1.0), `events`, `models`, `sources`, `topics`, and `observations` (1.2.0).

## Field grades / 字段分级

Each property carries `x-grade`:

- `quote` — original words from the source, checked against it
- `excerpt` — shortened or reformatted from a source (names, counts, metadata as the source gives them)
- `machine` — written or proposed by our pipeline; unreviewed unless the record's `review_state` says otherwise
- `human` — confirmed by a person on record
- `record` — our own bookkeeping: ids, timestamps, versions, vocabulary state

## Wire rules / 线上规则

- Every declared field is always present. Unknown is `null`; a key is never dropped to mean unknown. `0`, `""` and `[]` are real values (`rule:three-states-are-not-zero`).
- One declared exception: `Event.announced_at` is written only for updates with no `occurred_at` (marked `x-key-optional`), so dated updates stay byte-identical.
- Fields marked `x-shape: view` are denormalised snapshot fields (joins and rollups such as an organisation's name, claims on a topic). Their nested shapes are not frozen in 1.0.0; they are replaced when the snapshot is rebuilt around observations.
- `observations.json` publishes only the head of a merge (#25). An observation found to be the same as an earlier one is not a row of its own; its id appears in the head's `merged_from` and redirects there, and the head carries its sources and facts. Catalog entries in `concerns` are machine-proposed candidates; one a person rejected is dropped, and so is an observation a person rejected.
- `SourceAccount.identity_url` is typed `uri` in the ontology, but 31 of 374 rows hold the evidence note that found it. The contract states the wire truth (`x-wire-range: text`) until the data or the ontology is corrected.

## Versions / 版本

Four versions, never merged. Every `search` and `record` response returns them as `versions`:

| Version | Meaning | Source |
| --- | --- | --- |
| `contract` | field names, types, grades | `public/contract/v1/index.json` |
| `ontology` | the schema the records conform to | snapshot manifest `schema_version` |
| `method` | how readings were computed | snapshot manifest `method_version` |
| `data` | the published release the answer came from | the loaded release id |

In the snapshot manifest, `ontology_version` is the sealed catalog package (1.0.0 lineage) and `schema_version` is the type definition; `contract_version` records the contract the snapshot was written against.

A field added in a minor version is optional for readers to use. A field is deprecated for at least one minor version before it is removed. A breaking change moves the path (`/contract/v2/`).

## Changes / 变更

- 1.7.0 — each `concerns` entry of an observation carries `occupation_id`: the occupation a `task` belongs to, `null` for other kinds (#32). Occupation pages and `occupation_summary.tasks` count a task only under its own occupation; with an older release, a task counts under an occupation only when it is the observation's one occupation.
- 1.6.0 — `occupations.json` rows carry `alt_labels_en` and `alt_labels_zh_cn` (Occupation.alt_label, ontology 2.6.0, #30): O*NET reported job titles as written, and their AI translations and model-proposed common Chinese names. They find an occupation and do not define it; one name can belong to several occupations. `null` when the release carries none. The snapshot manifest records which sealed release they came from (`alt_labels_from`). Search responses list the other names a query used under `aliases`, and the `occupation` argument accepts them.
- 1.5.0 — search returns observations; each result carries `matched` and `title_language` (#30).
- 1.4.0 — `changes_since`; `query_observations` takes `recorded_since` and `order=recorded` (#29).
- 1.3.0 — `query_observations`, `occupation_summary`, and `get_record` for observation ids (#29).
- 1.2.0 — `observations.json`: Observation rows with `sources`, `facts`, `concerns` (candidate market work items, occupations and O*NET tasks) and `merged_from` (redirects). Additive: a reader of 1.1.0 is unaffected.
- 1.1.0 — `work.json` and `occupations.json` without levels; `Event.work` links (#35).
- 1.0.0 — first contract (#27).

## Checks / 校验

- `pnpm data:contract [dir]` validates a snapshot directory against the schemas (rows of every snapshot file listed above, id uniqueness).
- `pnpm data:release` and `pnpm data:local:release` run it first and refuse a snapshot that does not conform.
- `scripts/tests/public-contract.test.mjs` covers the generator and the validator; `site-output.test.mjs` checks the served files and that live responses match the OpenAPI.
