# 观察质量评估与公开复核状态

本规范对应 [#26](https://github.com/feyn-machines/surviagi/issues/26)，承接[证据账本设计](../superpowers/specs/2026-11-02-evidence-ledger-redesign.md)、[观察验收规范](observation-acceptance.md)与 [2026-11-05 窗口核对](../data/observation-window-review-2026-11-05.md)。它定义下一阶段实施与验收口径，不代表评估器、报告接口或回归门禁已实现。评估对象是观察，不再计算等级。

负责人已决定：暂不占用负责人人工复核时间，暂不接受外部复核。Agent 可以逐项评估并公开汇总，但必须注明评估者、方法和局限；不得因此写入 `human_confirmed` 或 `human_rejected`。模型间一致率、引用命中率与人工准确率是不同指标。

## 两类样本与优先级

每次评估冻结数据版本、生成时间、代码提交和有效观察总体：沿归并重定向取当前头、排除驳回，按稳定 ID 去重。保存总体 ID 清单及 SHA-256，后续归并不悄悄替换已冻结样本。方法身份包含抽取器版本、提示词哈希、模型标识、本体版本及映射方法；混合版本分别报告，版本未知单列。

总体样本沿用 #25：排序后以固定种子随机抽 50 条，不足则全查；保存种子、抽样算法与运行环境版本。方法版本升级时保留旧样本作回归，并从新版本总体独立抽样；旧样本不能兼作新版本未见样本。固定基准与本次随机结果分开报告。

风险队列另列，不用于估算总体准确率：

1. 已有明确证据错误或来源绑定失效、正在影响公开统计或引用的观察。
2. 被统计页或 Agent 实际引用最多的观察；使用同一固定时间窗内的计数，标明来源、去重规则和缺失值。
3. 数值型观察、反面证据，各补最多 10 条；再补非 X、归并和三个职业缺口，沿用 #25 的补样规则。

没有引用遥测时，引用次数必须标为未知，不能把页面出现次数或搜索排名写成实际访问量。可暂按已知页面关联数、最近变化时间和稳定 ID 排序，注明这是代理排序。补样与总体样本重合的只评一次，保留全部入选原因；两类分母分别统计。

## 评分与报告

每项保留精确来源捕获哈希、观察内容哈希、原始输出及评估版本。正文与逐条评估留本地私有目录，公开安全的聚合结果与必要来源链接。不能只用“同 source_id 的任一保留文本命中”冒充精确捕获绑定。

| 维度 | 通过条件 | 常见失败 |
| --- | --- | --- |
| 引用 | 原文引文在绑定捕获中可定位，未改变说话者与语境 | 引错捕获、转述变作者自述 |
| 数值与单位 | 值、比较符、量级、单位、分母、时间和基准均有支持 | 串文编号当成绩、超过 8 变成 8 |
| 主体与工作 | 一个行动者、一次具体工作尝试，产品未知可保留未知 | 多主体多任务混合、普通安装体验当 AI 工作 |
| 任务映射 | 来源支持具体任务及职业关系，泛称不强配 | 一般工具体验被计为完整职业任务 |
| 证据类型 | 自述、演示、生产使用、测量等符合定义 | 计划变已使用、厂商宣称变独立测量 |
| 方向与结果 | 保留成功、失败、未知与条件，方向有原文支持 | 耗时变成功、限制被改成支持证据 |

每维判为通过、失败、不适用或无法判断，并留原因。没有数值才可将数值维度标为不适用；缺失或打不开证据是无法判断，不能从分母静默删掉。任务缺乏足够描述时也要区分合理留空与错误映射。

报告每维通过/失败/无法判断/不适用的数量，以及通过数 / 全部适用样本数；无法判断留在适用分母中，同时可另报已判定子集的比率并明确其分母。整条全对要求所有适用维度通过，任一无法判断不能算全对。样本量、总体规模、覆盖窗口、抽样方式和评估者身份必须与比率一起给出。

Agent 评分称“Agent 评估通过率”，不称人工准确率或独立真值。若未来有独立人工标注，再公开人工准确率及抽样不确定性；当前不据 Agent 判断推断真实总体准确率。无结果材料的漏抽检查单独按 #25 执行，不能由产出观察样本推算召回率。不同版本样本或评估者不同，不直接声称质量提升。

公开报告必须显式区分：本次结果、历史结果、尚未评估。未覆盖的方法版本不能继承旧版比率；Agent 返回的报告链接须指向匹配的方法版本，未评估则说明未评估，不填 0% 或 100%。新增公开字段及端点须同步契约与中英说明，本规范没有预先宣布可用 URL。

## 回归集与变更门禁

将已确认错误改写为不包含第三方原文的合成最小案例，记录来源问题类别、预期结构、适用方法版本和修复提交。2026-11-05 Agent 初查仅提供待验证候选，不把它的每个判断直接登记为人工确认。

首批场景：串文编号/日期/排名不作为任务分数；保留不等式与中文量级；数字环境演示不映射实体工作；多模型多任务拆分；一般软件体验不抽 AI 工作；未来计划不当已自用；耗时不推出成功；负面结果与人工介入保留；重复事实归并且相反结果不合并。

规则或提示词变更须重跑固定回归集，保存输入/预期/实际/方法与执行结果。确定性解析测试与真实模型输出评估分开，禁止将未调用模型的 fixture 测试说成提示词质量验证。模型评估允许合理措辞变化，关键主体、数值含义、类型、方向和拆分边界不能退化。关键案例失败阻止该变更交付；不能通过改掉预期或删除难例恢复通过。此门禁尚待实现，不宣称现有 `pnpm check` 已覆盖。

## 复核状态与发布验收

现有 Agent 观察投影已有 `review_state`、`reviewed_at`；三状态使用现有契约枚举。Agent 评分另存评估记录，不改人工状态。未来人工复核必须绑定内容哈希、方法版本、操作者与时间，追加历史；内容变化后旧确认不得自动覆盖新内容。沿归并链迁移确认也必须显式核对，不能凭 ID 继承。

驳回观察应退出有效计数、职业/赛道页面、话题证据与普通 Agent 检索；重算派生结果，并保留历史发布可追溯性。精确 ID 查询和历史快照如何表达驳回，须在实现时统一契约与页面说明，避免仍被当作当前有效证据。不能只过滤列表却保留摘要缓存中的旧计数。
