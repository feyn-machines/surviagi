# Fixed knowledge versions and shared reads

The website imports the independent public knowledge repository only for an explicit integration task. It never follows its default branch at request time. Merging a content PR does not update the website or prove the content true. The importer implements the [formal contract](knowledge-contract.md); synthetic test records never become website knowledge.

## Candidate import

Run `pnpm knowledge:import --commit <full-40-character-knowledge-SHA> --website-commit <full-40-character-integration-base-SHA> --output <candidate-artifact-path>`. For every subsequent integration, add `--previous <last-accepted-artifact-path>`. Supply `--cache <verified-artifact-path> --cache-index <trusted-index-hash>` to permit an offline retry for the **same** knowledge commit. The CLI reports whether it fetched or used the pinned cache, and whether accepted history was supplied. Paths should be inside an ignored local directory. The output is a candidate, never an activation or a replacement of accepted history.

The fixed remote is `https://github.com/feyn-machines/surviagi-knowledge.git`. Trusted website tooling creates a temporary bare Git repository and fetches only the requested commit. It reads objects with `ls-tree` and `cat-file`, without checkout, hooks, filters, submodules, package installation or executing content scripts. Only the formal `questions/`, `cases/`, `answers/`, `updates/` trees and `withdrawals.json` contribute. Other files are ignored. Unexpected files inside formal trees, symlinks, executable blobs, submodules, malformed paths, mismatched IDs/hash directories and duplicate JSON keys fail the candidate. Budgets: 10,000 formal files, 1 MiB per blob, 16 MiB total; tree enumeration is capped at 18 MiB / 100,000 entries, Git operations at 60 seconds each.

Every revision's bilingual content hash and references pass the contract. The previous accepted artifact checks append-only history. A verified cache must match the requested SHA, contract and externally pinned index hash (from the accepted website pin, never from the untrusted cache itself); only a transport fetch failure permits fallback, never invalid fetched content. The candidate is written through a temporary file and atomic rename. Failure preserves existing candidate/accepted files and never changes a live pointer.

An artifact contains `format: 1`, the knowledge `commit`, `websiteCommit`, full normalized `bundle`, exact-revision `reverse` dependencies and `indexHash`. The index hash binds every field except itself, using the contract's canonical JSON v1 serialization and SHA-256; verification reconstructs the reverse index too. `websiteCommit` identifies the website integration base selected before generation (the artifact cannot embed the future commit containing itself); the existing code release identifies the final integration commit. Keep accepted artifacts and deployment pins in trusted website storage. These integrity checks detect corruption; hashes are not signatures and cannot establish trust if an attacker can rewrite both the artifact and its expected provenance.

No real content is imported by this change: the knowledge repository may be empty. First publication requires a real accepted artifact and an explicit site integration/release task. Existing kg imports remain independent.

## Shared reader API

`createKnowledgeReader(verifiedArtifact, loadBaseline?)` exposes `get({id, revision?}, language)` and `search({query, language, kind?, direction?, nature?, limit?})`. Both page and Agent adapters must call this API. Languages are `en` and `zh-CN`; omitted revision follows the artifact's current head. An exact historical read returns `superseded`; search considers only current heads, selected language title/body and optional filters. Query matching is Unicode NFKC normalized, case insensitive substring matching, including Chinese text. Default result limit is 20, maximum 100. Results carry knowledge commit, website integration base, index hash, language and withdrawal generation. Details include the same shared facts and one localized body. Ordering is deterministic formal-path order, not a relevance score.

The reader owns a defensive copy; mutating inputs or returned objects cannot change future reads. Every call reloads the shared baseline, applies roots plus stored exact-revision impacts and computes transitive closure using this artifact's reverse graph. New candidate edges are therefore filtered even when absent from an earlier affected list. Corrected revisions without bad dependencies can be visible; affected historical revisions remain hidden. Root withdrawals from the artifact also apply and cannot reverse shared tombstones. A withdrawn read returns identity/provenance, `status: withdrawn` and a public reason **only**, without title, body, summary or facts. Search omits it entirely. Missing/corrupt baseline rejects the whole knowledge call, including search and unknown IDs.

The default baseline loader reads `/opt/openaiwill/shared/knowledge-withdrawals.json` afresh per operation, outside code release directories. Its exact shape is `{generation, updatedAt, withdrawals, affected}`: generation is a nonnegative safe integer; updatedAt is a UTC ISO timestamp; withdrawals use contract `{target:{id,revision},date,reason}` entries; affected is an array of exact `{id,revision}` references. Unknown roots/impacts are valid, because a rolled-back artifact need not contain newer revisions. Duplicate roots/impacts, invalid dates/identities and missing fields reject reads. Initial generation zero and empty lists must be explicitly created by trusted deployment tooling, never inferred from a missing file. The loader does not initialize or write the baseline.

The authorized publication task must maintain a monotonic baseline with atomic replacement under the same server lock as promote/rollback, preserve roots/impacts and recompute candidate dependencies before switching. This library does not change the existing release scripts, initialize server state or deploy knowledge. Release integration and end-to-end HTML/Markdown/HTTP/MCP acceptance belong to the [#112](https://github.com/feyn-machines/surviagi/issues/112) and subsequent rollout tasks. Adapters must map baseline errors to 503 and send `Cache-Control: no-store` for all knowledge outputs (including search, summaries and status responses), with no cross-request response/body cache. The unfiltered immutable index may be retained; no response may bypass the reader.

## Rendering boundary

Markdown remains untrusted inert text. `renderKnowledgeText` escapes all HTML-significant characters; use it only as text inside a preformatted block (`white-space: pre-wrap`), never as an attribute or script. React adapters can use escaped-by-default text nodes instead. This initial policy deliberately does not interpret Markdown or autolink bare HTTP/HTTPS text. A richer renderer needs a separately reviewed allowlist; the contract's syntax check alone is not a sanitizer. Do not fetch linked resources or render HTML, embeds, includes or images from content. Public withdrawal reasons are also text and must be escaped by adapters.

An emergency withdrawal hides subsequent reads without rebuilding or rolling forward code. It cannot delete responses already delivered, third-party caches, or public Git history. Verify rollback behavior and live baseline failure handling before the first knowledge release. `pnpm knowledge:test` covers import/history/cache, real local Git object reads, CLI failure preservation, file baseline replacement, transitive/new-candidate withdrawals, corrected heads and safe text. It is not real content or production acceptance.
