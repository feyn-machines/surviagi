# 观察抽取与真实窗口验收

本规范对应 [#25](https://github.com/feyn-machines/surviagi/issues/25)，落实[证据账本方法](../data/evidence-ledger-method.md)。它规定后续验收怎样留证，不报告新的准确率，不代表历史回填或非 X 抽取已经完成。字段、受控词表与空值表达以本体及生成的[公开契约](../../public/contract/v1/index.json)为准；本文件不新增枚举或数据库字段。

## 抽取单位与边界

一份来源可产生零到多条观察。一条观察对应一个主体、一个被使用的产品或模型、一个具体工作尝试；不同任务、不同尝试或不同结果不要因为同帖而合并。主体是实际行动者或声称者，不默认等于转述账号。产品未具名时保留未知，不能从账号或上下文猜具体版本。

每条核对主体及其与产品的关系、原名、工作描述、具体任务、动作、结果、条件、证据类型、发生时间、发布时间与来源引用。结果未说明时保留契约规定的未知值，不能将“发布功能”写成“成功完成工作”。职业和任务映射可以为空或候选；候选映射不能在报告里计为人工确认。

| 材料 | 抽取与复核重点 |
| --- | --- |
| 公司官方帖、博客或演示 | 自述与演示分开；自家使用不自动成为独立测量；功能清单、价格、发布日期单独出现不算工作结果 |
| 采用方、从业者 | 有具体自身尝试即可，没有数字也可成立；具名生产使用与个人试用分开；转述保留原行动者 |
| 研究、第三方评测、市场测量 | 保留机构、样本、任务、产品版本、比较基准和统计期间；排行榜名次不能冒充完成率 |
| 非 X 文档 | 绑定精确正文快照，遵循[非 X 来源规范](non-x-sources.md)；RSS 摘要不能被当作未下载全文的证据 |
| 失败、回滚、限制、事故 | 与成功采用同一纳入标准；保留人工介入、失败条件和损失，不因负面结果过滤 |

引文必须可在绑定的来源正文中找到；翻译与原文分开。数值除了字面可找到，还要人工核对含义、单位、分母、比较对象与时间：串文编号、日期、排名、点赞数不能只因出现数字就成为任务成绩。来源证明“有人这样说”，不证明结果被独立复现。

## 去重、事件与话题

同一事实的多来源保留一条观察和全部来源边，不能把转载数当独立尝试数。现有抽取/映射归并依据主体、对象、工作与日期寻找候选；跨 X 与文档还须核对具体任务、结果、产品版本和条件。不确定时保留分开的记录及候选关系，不能声称现有键已充分解决语义归并。

验收要成对覆盖：同事实跨来源、同帖多任务、不同日期的重复尝试、同日不同条件、相反结果、未具名产品与具名版本。归并保留首个稳定 ID、历史重定向及所有来源；重复导入不新增观察或重复数值。相同数值但不同单位、比较基准或不同尝试应分别保留。

事件描述发生了什么，一件事件可以有多个观察；观察也可独立于公司更新存在。没有事件关联不应成为丢弃个人实测的理由。话题选项的支持/反驳应来自观察及其引用，机器判断保留候选状态；测试合并重定向只计一次、无关观察不连边、人工驳回不再公开。事件相关不等于已经支持某个话题答案。

## 真实窗口报告

先固定窗口起止和时区、来源清单、输入快照哈希、采集完整性、模型标识、提示词哈希、本体/映射版本、抽取运行 ID 和代码提交。失败或未耗尽分页的来源单列，不能作为“没有观察”。开发使用私有本体副本和克隆数据库，不对日常库做实验。

报告至少包含以下分母和阶段计数，保存可复查的本地明细；公开仅给安全汇总和允许的引用链接：

1. 来源总数、成功/失败/部分成功数、原始材料数、预筛候选数、已读数、失败待重试数。
2. 抽取候选数、校验拒收数及原因、入库数、归并数、有效观察数；来源数和观察数分别计数。
3. 有效观察按本体证据类型、结果方向、来源类型分布；未知单列。多职业映射总和不得冒充去重总数。
4. 会计、客服、软件开发各列稳定职业 ID、候选/确认映射数量、证据类型分布与可打开来源的观察清单。缺职业覆盖如实列缺口，不强配泛泛的工作描述。
5. 请求数、输入/输出及缓存 token、实际计费模型、运行日期、失败重试和费用；历史费用只能作为对应日期估计，不能沿用为当前报价。

准确率抽查建议：固定种子从全部有效观察随机抽 50 条（不足则全查），另对负面、非 X、数值、归并和三个职业各补最多 10 条。补充样本与随机样本去重但分别报告，不能混算成总体准确率。记录抽样总体、种子、选择方法、样本 ID 和逐字段判定。

分别报告引文准确、数值语义准确、主体/证据类型准确、任务映射准确和整条全对的分子/分母；不适用字段不进对应分母。引文命中率不能代替语义准确率。再从已读但无观察的材料随机抽 50 份（不足则全查），人工标注应抽观察，报告漏抽例数；关键词补查另列，不据此声称总体召回率。此处样本量是验收建议，不是已确认的质量门槛或已有结果。

## 历史回填与版本

早期讨论要求观察并入更新抽取；#25 后续 PR #50 的实测改为独立调用，保留更新原流程。不得恢复旧的同次调用假设作为验收依据。

历史回填是对“定义向前生效”的显式、有版本的一次例外：读取旧材料生成新的观察运行，不覆盖旧更新、旧定义标记或已发布快照，不把回填写入时间当作事实发生时间。2026-11-03 的 500 条成本试验与全量单遍建议见 Issue 评论；当时的数量和费用不是当前输入规模或已授权范围。当前 Issue 尚无负责人确认回填范围的记录，执行前需确认范围并重新给出未读材料数及预算；不能把 `--all` 当作日常默认。

先使用 `extract-observations` 的 `--plan-only` 核对所选窗口/范围，再在克隆库做有界试验。运行留不可覆盖记录；同运行重导应幂等，失败批次仍可重试，显式重读不得改写旧运行。批准历史范围后按该范围执行并做前后对账，区分新增事实与方法更新；只有新增运行记录和最终快照均可追溯，才算回填完成。

## 完成条件与验证证据

`pnpm check` 和 `pnpm data:setup`、`pnpm data:test` 是代码/管线交付检查；真实数据库测试使用克隆库。重点覆盖抽取零到多条、反面证据、引用拒收、数值误判、归并及幂等、候选映射、话题正反证据和非 X 输入。现有测试入口位于 `scripts/tests/test_data_observation_*` 与 `test_data_topic_observation_evidence_integration.py`；列出入口不等于这些场景均已覆盖。
