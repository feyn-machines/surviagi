# 非 X 来源接入与官方发布对账

本文件是 #24 的实施与验收规范，尚不代表采集器已接通。首批范围沿用已确认决定：
客户案例页、官方博客 RSS、外部指数与研究报告；不用付费来源。
现有产品目录的人工来源录入不算自动采集验收，X 时间线成功也不代表官方发布覆盖完整。

## 来源选择与运行边界

| 来源 | 首批处理方式 | 运行频率建议 | 条款、成本与限制 |
| --- | --- | --- | --- |
| 官方博客 RSS/Atom | 发现文章链接，下载允许访问的正文；摘要 feed 不冒充全文 | 随既有两次采集窗口，使用条件请求 | 免费公开端点；登记站点条款和 robots 核查日期，不绕过登录、付费墙或反爬 |
| 客户案例页 | 从厂商案例索引发现详情页；保留具名采用方及出处 | 每窗口检查索引，正文按内容变化增量处理 | 免费公开页面；厂商案例属于厂商提供的采用证据，不自动视为独立验证 |
| 外部指数与研究报告 | 人工登记发行页及版本，采允许访问的 HTML/PDF | 每窗口检查已登记发行页；新版本单独入账 | 免费可访问版本；PDF 解析失败单列，保存口径、样本、产品覆盖与研究机构 |
| 官方 changelog、价格与可用性文档 | 先作为发布对账基准；逐项登记稳定入口 | 与上述相同窗口核对 | 页面变更不等于产品发布；价格需保留币种、计费单位、地区和截至日期 |
| GitHub releases、arXiv、评测榜 | 后续候选，不计入首批接入完成数 | 接入前另定 | 分别评估 API 限额、版本与撤稿、榜单方法和转载许可；公开可读不等于可再发布全文 |

首批试点建议选一个厂商的官方博客和 changelog，优先验证 RSS 路径；案例和报告随后接入。
Anthropic Economic Index、Microsoft Working with AI、Google ATLAS、OpenAI 使用研究、
NBER/央行调查属于待核对目录，不能把这些名称当作已接通端点或当前版本清单。
每个端点启用前必须记录 URL、官方归属依据、来源类型、允许抓取范围、条款 URL、
核查日期、限速、解析器版本和责任组织；无法确认时保持未启用。网络、存储及解析也有成本，
每轮报告请求数、字节数和耗时，不宣称零运行成本。遵守 Retry-After、限制并发和重试次数。
本工作不新增或修改两个既有定时任务。

## 身份、版本与失败恢复

以下是待实现的逻辑字段，最终字段名和词表从本体生成，不能在代码里另立枚举。
来源身份与采集快照分开：`collected_sources` 已按 source_id 唯一（迁移 022），
`collected_captures` 保存逐轮快照；新增来源应沿用这个边界。
现有 kind 约束、账号外键、抽取候选选择和公开投影须一起检查，不能把网页伪装成 X 账号或帖子。

- 来源 ID 由来源命名空间和规范 URL 的摘要确定。只去明确登记的跟踪参数；保留语义参数，
  保存原 URL、最终 URL、重定向及规范化规则版本，不凭标题合并来源。
- 同 URL 的正文变化形成新快照，保留响应哈希、正文哈希、抓取时间、解析器版本及本地原文引用。
  抽取输入绑定精确快照和方法版本；旧正文、旧观察不覆盖。
- 原始发布时间、修改时间、抓取时间分别记录。未知发布时间保持未知，不能拿抓取时间补作发布时间。
  若现有 NOT NULL 不允许未知，先迁移或明确拒收，不填假日期。
- HTTP 304 只复用已验证的本地快照；首次无快照的 304 视为失败。200 空正文、解析失败、
  登录页、截断和重定向到未登记域名都不能标成成功。
- 每轮保留端点结果、分页游标、失败原因及重试次数。仅在正文落盘、哈希校验和事务提交后推进游标；
  失败重跑复用成功输入，重复导入不新增来源、快照或观察。索引分页未耗尽必须报 partial。
- 全文、PDF 和原始 HTTP 响应只存忽略目录；公开只允许经投影检查的摘录、引用与链接。
  禁止把 feed 全文、正文或本地路径透传到快照、Agent 响应和 GitHub。

## 跨来源归并与主来源

一个来源可以产生多条观察。同一事实跨 X/博客重复时合并观察来源边，保留双方 URL、
精确引用、抓取版本、抽取运行和归并方法；不能因为同一 URL 就把文章里的所有事实合成一个。
候选归并比较主体、明确对象版本、动作/任务、结果与发生时间。链接相同只能帮助发现候选，
标题相似或发布日期接近不足以自动合并。冲突数值、不同产品版本、地区与发布阶段分别保留，
不确定的归并建议留待复核。归并使用现有观察身份和合并机制，不能重新编号或删除历史观察。

主来源优先选择直接支持该事实、可公开打开的第一方非社交原始页面；随后才是 X。
不能按 URL 字典序挑主来源，也不能把研究转述页优先于原报告。只支持部分事实的页面不能
替代其他事实的出处。厂商客户故事须记录发行方与采用方的不同身份；厂商自述和自家产品样本
研究不能因网站平台变化升级为独立证明。研究观察附样本、统计期间、分母、方法和覆盖边界。

## 官方发布对账

以公司、固定 UTC 半开窗口 `[start,end)`、官方索引 URL/版本和采集截止时间为单位生成本地报告。
先冻结官方基准清单和哈希，再检查来源及观察；同一发布多个页面按显式发布标识或人工确认归组，
不能拿页面数当发布数。网页无发布时间、索引不完整或抓取失败时，报告基准不完整并列未知数。

每个基准发布记录官方 URL、标题、发生/发布日期及其依据、对应来源 ID、观察 ID、匹配依据和状态。
状态至少区分已匹配、未采正文、已采待抽取、已抽取待归并、明确不在范围、未知。
“明确不在范围”须有原因，不计作已匹配；没有 X 帖子不等于漏采，已有非 X 观察即可能覆盖。

报告列出基准总数、在范围数、已匹配数、各漏采阶段数、未知数及排除原因；
在范围总数须等于已匹配与各未完成阶段、未知数之和。分母不完整时不得给出全公司完整覆盖率。
补采沿正常导入与抽取链路重跑，再用**同一基准清单**生成 after 报告，逐条关联前后状态，
保留 unresolved，不只报告“补采成功”。可公开摘要仅含窗口、基准链接、计数、方法与局限，
不上传正文、内部路径和原始报告。

## 后续实现验收

1. 在私有 datasets 副本和 `OAW_DATA_DATABASE` 克隆库接通至少一种真实非 X 来源到事件/观察抽取。
   记录真实运行时间、端点、窗口、来源/快照/观察计数；合成 fixture 不代替真实接入结果。
2. 验证同输入重放、同 URL 正文更新、304、分页中断后恢复、限流、坏 PDF、事务失败后重跑；
   计数与哈希证明幂等，旧版本仍可查。跨来源重复事实一条观察保留两条来源，
   不同版本或冲突结果保持分开；引用须逐字存在于绑定的正文快照。
3. 对选定公司输出 before/after 对账，保留至少一个真实漏采的补采状态，
   若窗口实际零漏采则如实报告并另用回归用例验证恢复，不虚构真实漏采。
4. 检查本体到数据库、公开契约、快照、Agent 来源与主链接一致；旧发布兼容；
   公开字段无全文。按仓库要求运行 `pnpm data:setup`、`pnpm data:test`、`pnpm check`
   和 `pnpm security:staged`，记录真实克隆库结果。此文档阶段没有运行这些集成验收。
5. 合并后按既有共享本体/迁移串行约定更新日常输入；代码与数据在既有发布窗口验收，
   全部条件满足再关闭 #24。观察语义抽取归 #25，人工质量评估归 #26。
