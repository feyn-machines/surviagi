## 1. 为什么改

现框架把每条官方更新路由到 614 条“赛道活动”，由模型给出 L0–L5，任务取最低值，再汇总到职业。问题：

1. **回答的问题没人问。**例：“会计师与审计师”30 项任务——L1 8、L2 1、未知 15、未触及 6。读者和 Agent 都无法据此回答任何事。
2. **测的是厂商发了什么，不是能力。**厂商自证封顶 L2，所以等级主要反映“我们关注的厂商有没有提到这块”。全站最高 L3。
3. **精确的外观包着未复核的噪声。**每条更新 614 次机器判断，复核数 0。
4. **有用的证据在边上。**采用方、从业者实测、第三方测量要么不进等级，要么只进话题。
5. **搜索引擎同样不认可。**Search Console（第 2.4 节）：站点地图里大多数地址没有被收录；模板化短页被判为不值得收录。

## 2. 数据支撑：核心问题怎么定

### 2.1 人在问什么
- 我们从 X 挖出的 202 个话题：120 个是“AI 会不会取代某职业”，82 个是“某类生意还能不能做”。参与账号最多：呼叫中心 35、软件工程师 35、中层管理 18、卖软件的生意 16、客服 15、律师 11、会计 10。
- Pew（2024 调查，2025-02 发布）：52% 在职者担心 AI 对工作的影响，32% 认为自己的机会会变少，6% 认为会变多。
- 自有搜索（2.4）：真实查询分两类——“会不会被 AI 取代某职业”（律师助理、游戏开发、软件工程师、SaaS）和新产品/模型名称。

### 2.2 别人回答了什么
Google ATLAS（2026-07，约 1,500 万次 Gemini 交互）、Microsoft “Working with AI”（20 万 Copilot 对话）、Anthropic Economic Index、OpenAI “How People Use ChatGPT”：都只用**自家聊天产品日志**，回答“人在聊天框里让 AI 帮了什么”。共同结论：触及职业广、每个职业触及任务浅、端到端完成少（Google：<10%）。看不到企业部署、Agent、API 生产使用。**未找到跨厂商、带日期与出处、按职业整理的真实部署与实测记录。**这是我们的位置；这些指数本身也作为“测量”类证据收录。

### 2.3 我们现在能供给什么
2026-11-02 数据版本：1,144 条更新，仅 42 条有“任务 + 结果”。依据分布：厂商自述 307、生产使用 32、演示 10、实测 9、亲自使用 5，其余 781 条早于 10-07 或非使用类未记录。字段已有（主体、依据、任务、结果、带原文引用的数值），**缺的是来源**：主线只读厂商官方号。

### 2.4 Search Console（2026-10-07 至 11-02）
- 10 月中旬的展示量绝大部分来自“公司名+数字”类自动化查询，落在少数更新页；10-23 前后这些页被移出索引，展示随之消失。技术面正常（抓取、robots、规范网址、无 noindex、期间无代码发布、无 Google 算法更新）。
- 真实读者查询很少，但已出现两类：“会不会被 AI 取代某职业”和新产品/模型名称。
- 收录抽样：约四分之一已收录，其余为“已抓取 - 尚未编入索引”或 Google 尚未发现。
- 明细数字保存在本地，不公开。

### 2.5 结论：核心问题
> **“AI 会不会接手[某职业 / 某类生意]？现在的真实证据是什么——谁在用、做到哪一步、结果数字、反面证据。”**

问题沿用读者的问法（搜索与 AI 助手的入口）；回答只用有出处的证据（区别于各家聊天日志指数）。

## 4. 数据模型

### 4.1 核心单位：观察（Observation）

一条观察 = **一个主体用一个对象在一项工作上做了一件事，结果如何，依据什么，出处在哪**。一条来源可产生 0..n 条观察；同一事实的多个来源合并为一条观察。

| 字段 | 说明 | 取值/约束 |
| --- | --- | --- |
| `observation_id` | 稳定 ID | `obs-` + 内容身份哈希（主体+对象+工作+发生日期） |
| `actor` | 谁做的 | 组织或人物 ID；未入库时为名称 + `unresolved` |
| `actor_role` | 主体在这件事里的身份 | `maker`（出品方）/ `adopter`（采用方）/ `practitioner`（从业者个人）/ `evaluator`（第三方测评）/ `researcher`（研究/统计机构） |
| `subject` | 用的什么 | 产品或模型 ID（产品与模型分开，见 4.2） |
| `work` | 在什么工作上 | O*NET 职业与任务引用、或我们的赛道；`candidate`（机器映射）与 `confirmed` 分开 |
| `task` | 具体做了什么 | 一句白话 |
| `evidence_type` | 依据 | `vendor_claim` / `demonstration` / `own_use` / `production_use` / `measurement` / `statistic`（沿用 event_basis：`measurement` 含义不变，仍指出品方以外的人做的测试；新增 `statistic` 指机构对采用、花费、就业的统计测量） |
| `outcome` | 结果 | `succeeded` / `partly` / `failed` / `not_stated`（沿用 event_result） |
| `direction` | 对核心问题的方向 | `ai_takes_on`（AI 接手更多）/ `human_still_needed`（仍需人或失败）/ `neutral` |
| `facts[]` | 数值 | 值、单位、指的是什么、比较基线、口径、原文引用（引用必须在来源中找到） |
| `scale` | 规模 | 用户数、调用量、员工数、覆盖比例等，可空 |
| `conditions` | 条件与限制 | 人工监督、试点范围、地区、失败模式 |
| `occurred_at` / `announced_at` / `observed_at` | 三个时间分开 | 缺失为 null |
| `sources[]` | 出处 | 来源 ID、URL、原文引用、来源类型（X / 官方博客 / 案例页 / 报告 / 论文） |
| `review` | 复核状态 | `machine_proposed` / `human_confirmed` / `human_rejected` + 时间 |
| `extracted_by` | 方法版本 | 抽取器、提示词哈希、模型 |

与现有结构的关系：现有 `Event`（更新）保留，作为“发生了什么”的事件；观察挂在事件上（一个事件 0..n 条观察）。现有 `EventFact` 升级为观察的 `facts`。2026-10-07 起的“依据/任务/结果”字段就是观察的雏形，不另起一套。

### 4.2 补齐的实体与关系
- **Product**：产品与模型分开（已有规则 `rule:product-is-not-model`，没有类）。产品带日期的可用性（阶段、渠道、地区、适用用户）与价格。
- **采用关系**：组织 —采用→ 产品，带阶段（计划 / 试点 / 集成 / 生产）与规模，由观察支持。
- **投资关系**：投资方 → 被投公司，带时间；用于标注第三方是否独立。
- **人物任职**：人物 —任职→ 组织，带起止时间；判断讲话时是否代表公司。
- **测量**：外部指数与机构统计表示为 `evidence_type=measurement` 的观察，附口径（样本、范围、时间段）。

### 4.3 退役
等级、自主阶段、闸门、活动读数相关的类、词表、规则标 `until`（定义向前生效，不删除历史）；相应数据表保留但不再发布。614 条“赛道活动”作为**浏览分类**可保留（用来把观察归类），不再承载等级。

### 4.4 Schema 怎么升级：增量，不重建

按本体现有的版本规则（`datasets/ontology/VERSIONING.md`，本地），这次是 **minor 升级（本体 2.4.0 → 2.5.0）**，不是重建：

| 部分 | 处理 |
| --- | --- |
| 目录（赛道、活动、职业、任务、领域） | ID 全部不变；只改赛道显示名（名称修订），随下一次封版 |
| Organization、Person、SourceAccount、Post、Event、EventFact、Model、Provider、Topic、TopicOption | 保留，不改含义；`affiliated_with` 增加可选的起止时间 |
| 新增 | `Observation`、`Product` 两个类及其属性；关系“采用”“投资”“观察挂在事件/赛道/职业上”；`event_basis` 词表增加一项 `statistic`（词表自身小版本） |
| 等级、阶段、闸门、活动读数 | 标 `until: 2.5.0`：定义留在 schema 里、旧数据原样保留，只是不再写、不再发布 |

数据库：新增几条迁移（新表：观察、观察来源、产品、采用、投资），不删除、不改写任何已有表；等级相关表停止写入但保留。已采集的约 5.8 万条帖子、1,144 条更新和它们的数值事实都不动；观察是新写入的行，历史回填也只写新表。

发布：数据快照增加 `observations`、`products` 集合；`chain`（等级）在网站与 Agent 改完后停止发布。和以往一样先发代码、再发数据，旧代码遇到新集合不会出错的顺序在实现时验证。

真正需要 major 升级的情况（删除身份、改变既有定义）本设计里没有。

### 4.5 对外契约
- 公开实体：Observation、Event、Organization、Person、SourceAccount、Source、Product、Model、Occupation、Task、Market、Topic、Article。稳定 ID 跨数据版本不变；合并留重定向。
- 字段分级：原文引用 / 来源摘录 / 机器生成 / 人工确认，契约中逐字段标注。空值与 0 区分。
- 由本体生成 JSON Schema（每个实体）+ OpenAPI（HTTP 接口）；发布快照必须通过契约校验。
- 版本：契约、本体、方法、数据四个版本分开，每个响应都带。

## 6. 抽取与分析流程

```
采集（X 时间线 / X 搜索 / 案例页 / RSS / 报告）
  → 事件抽取（现有，保留）
  → 观察抽取（新）：每条来源 → 0..n 条观察，引用与数值逐字校验
  → 归并：同一事实多来源合并；与事件挂接
  → 工作映射：观察 → 职业/任务/赛道（向量初筛 + 模型判断，候选与确认分开）
  → 话题挂接：观察作为话题选项的正反证据（替代现在“更新 → 选项”的判断）
  → 统计：按职业/生意 × 证据类型 × 时间计数（确定性计算，不用模型）
  → 发布快照（契约校验）
```

- 停用：每条更新对 614 条活动的等级判断、闸门状态、任务最小值计算。
- 历史回填：对已采集帖子按新规则重抽一次（成本估算见第 10 节）。
- 质量：每个方法版本按固定样本估计准确率（引用是否在来源、数值与单位、工作映射、证据类型、方向）并公开汇总；已知误判写成回归用例；复核优先级：被引用最多的、数值型的、反面证据。

## 8. 给人看的结构：赛道 / 职业 / 话题 / 文章（SEO / GEO）

负责人 2026-11-02 确认：主结构仍是**赛道、职业、话题、文章**四个栏目。负责人说的“统计结果”放在赛道页和职业页里，不另设栏目。

赛道和职业是同一批证据的两个视角，两边都保留：
- **职业**回答从业者的问题：“我的工作会不会被 AI 接手？”从业者的实测、亲自使用类观察主要落在这里，按 O*NET 职业与任务归类。
- **赛道**回答经营者和投资人的问题：“这门生意会不会被 AI 改变、还能不能做？”具名采用方的生产使用（例：某医疗平台把医患音视频迁到某云）、面向该行业的产品、采用与花费的市场测量主要落在这里。“生意还能不能做”类话题（82 个，例如卖软件、SaaS 订阅、OTA）也挂在赛道上。
- 一条观察可以同时挂在赛道和职业上（目录里已有 257 个赛道映射到 751 个职业）。

### 8.1 赛道页 `/markets`、`/markets/<id>`
- 现有 265 个赛道（分属若干领域），每个下有 2–3 条活动（共 614 条）。活动不再打分，改为赛道页内的小节，用来给观察归类。工作页（`/work/...`）并入所属赛道页并 301。
- 页面内容：标题即问题（“AI 会改变客服中心这门生意吗？现在的证据”）；一段可被引用的结论（只陈述计数与代表性证据，不下预测）；按证据类型的计数（生产使用 / 独立测试 / 测量 / 亲自使用 / 厂商自述）与近 30/90 天新增；代表性观察（带数字、条件、出处）；反面证据单列；主要采用方与产品；市场测量；相关话题与文章；结构化数据 Dataset + FAQ。
- 名称：现在赛道名是目录式长名（“场所虫害与卫生防护”），不是人会搜的词。显示名改为常用说法，ID 不变。
- 收录：目前 265 个赛道中只有 105 个有任何证据。没有观察的赛道页可访问，但标 noindex、不进站点地图。
- 赛道列表页 `/markets` 就是赛道视角的统计页：按领域分组，显示各赛道的观察数与近期变化，并附覆盖说明。

### 8.2 职业页 `/occupations`、`/occupations/<code>`
- 结构同赛道页，问题换成“AI 会取代会计吗？现在的证据”。职业组页（`/occupations/g/<id>`）汇总组内职业。
- 职业下按任务列出观察；没有观察的任务不单独展示。
- 职业列表页 `/occupations` 就是职业视角的统计页。
- 外部指数（Google、Microsoft、Anthropic 等按职业或任务给出的读数）主要放在职业页，并标明口径（只覆盖某一家聊天产品）。

### 8.3 话题 `/topics`
保留现有话题页，主体改为“问题 + 正反观察 + 账号主张”。替代类话题挂职业，生意类话题挂赛道，两边互链。解决 #15 的疑似重复。只有一个账号主张、没有观察的话题不单独建页，并入对应赛道或职业页的“讨论中”。

### 8.4 文章 `/articles`
保留现有文章流程（预发布、审核、Agent 读取）。选题围绕话题与新观察；正文引用观察 ID，可跳回赛道或职业页。

### 8.5 首页与其他页面
- 首页：问题入口（输入职业或生意）、四个栏目入口、最近的新证据、精选话题与文章。去掉以等级为中心的沉浸式叙事。
- 更新（`/updates`）与声音（`/voices`）不进主导航：更新是证据流水，可从赛道、职业页和“最近的新证据”进入；声音（名单与来源）放到“关于/方法”下，说明我们在看谁、为什么。是否保留在主导航由你定（见 C16）。

### 8.6 收录规则（#36）
站点地图只列：首页与固定页、有观察的赛道和职业页、达到门槛的话题（≥2 个账号或 ≥1 条观察）、文章、有实质内容的更新页（有数值、或有任务与结果、或 ≥2 个来源；按 2026-11-02 数据约 290 / 1,144 条）。其余页面可访问但标 `noindex`。中文页正文仍是英文的不单独提交。

AI 用量（按本地库 2026-10-27 至 11-02 一周的实际运行记录估算）：

| 步骤 | 现在每周 | 新设计每周 |
| --- | --- | --- |
| 更新 → 614 条活动的判断（TypeSafe，分批请求） | 约 40,500 条判断（66 条更新 × 614）+ 等级读数 | **停用** |

不做：不新增定时任务；读取不触发采集或模型；数据不进 GitHub；不给“取代概率”或预测性结论。
